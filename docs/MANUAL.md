## 1. Что это и зачем

**Задача владельца:** модель справедливой стоимости акции ПАО «Корпоративный центр ИКС 5» (X5, Мосбиржа) и дашборд, которые (1) печатают справедливую цену с явными, обоснованными допущениями и честной мерой неопределённости; (2) показывают, что заложено в рыночную цену и что должно измениться, чтобы рынок оказался прав; (3) показывают, что даст ближайший отчёт, и копят честный зачёт прогнозов против наивных эталонов. Рамки: простая система, автономная работа, бесплатные GitHub Actions и Cloudflare Pages, без VPS и без секретов.

**Метод** перенесён из модели Магнита 850oa: стоимость бизнеса (EV) через APV на полугодиях, сетка «мир ставок × режим маржи × уровень capex», слои весов миров, распределение по суждениям книги, обратный DCF, «что даст отчёт». Отличия продиктованы X5 (`docs/MODEL.md` §15, основания — `docs/DECISIONS.md`): рычаг ≈1,1× EBITDA, капитал — ≈<!--=point.equity_share_of_ev p0-->67<!--/--> % стоимости бизнеса точки, поэтому цена акции — внутренняя стоимость без колла Мертона, а казначейский пакет (9,4 % выпущенных акций, одобрен к продаже) — в формуле цены: капитал получает выручку от его продажи по k × рыночной цены, акций — все выпущенные; маржа — скорректированная EBITDA до МСФО 16 без LTI, LTI — отдельной денежной строкой; дивиденды — по политике компании, объявленные — в требованиях с даты отсечки. 1 % EV — ≈<!--=band.center_ev.rub_per_1pct_ev_median r0-->45<!--/--> ₽ печатаемой медианы.

## 4. Как всё работает: конвейер

Подробно — `ops/README.md`: расписание, таблица шагов и что значит провал каждого, что где лежит, живые входы, ручные действия, грабли.

- **Когда:** `.github/workflows/pipeline.yml` — по будням вечером после основной сессии MOEX (время — `ops/README.md`, «Расписание»; GitHub может запустить расписание с опозданием), при push в `main` с изменениями `model/`, `data/`, `indicators/`, `ops/`, `requirements.txt` (кроме `*.md`), вручную — только с `main` (прогнать ветку — `gh workflow run ci.yml --ref <ветка>`). Один прогон за раз (`concurrency: pipeline`), идущий не отменяется. «Сегодня» прогона — день по Москве (UTC+3 в коде: `model.book.today()`, у сборщиков `indicators.live.msk_today()`; от пояса машины и переменной `TZ` не зависит).
- **Шаги:** состояние из ветки `data` → живые входы (`python -m indicators.live`) → тесты такта → сборка выпуска (`ops/build_release.py`) → проверка контракта → код прогона и голова `main` → публикация в `data` (`ops/publish.py`) → сверка через боевую дверь `/api/model` → артефакт прогона → keepalive расписания.
- **Тесты такта** — `-m "not network and not ci_only and not docs"`: тесты числа и контракта. Их берут из `main`: сломанный тест роняет конвейер. Пересборка фактов (метка `primary`) на раннере пропускается — первички там нет; причина пропуска — строкой в сводке прогона.
- **Код прогона и голова `main`:** Re-run прогона идёт на его исходном коммите; если `main` с тех пор ушёл вперёд правкой путей push-триггера (`model/`, `data/`, `indicators/`, `ops/`, `requirements.txt`, кроме `*.md`), шаг падает и выпуск на устаревшем коде не публикуется — его публикует прогон на новом коде. Повтор красного прогона — `gh workflow run pipeline.yml`, не Re-run.
- **Главное правило:** любой упавший шаг до публикации — ветка `data` не тронута, на витрине прежний выпуск; красный прогон — письмо GitHub (раздел 3). Каждый шаг кончается строкой «готово: …» или «ПРОВАЛ на шаге …: причина»; они же — в сводке прогона, туда же — запасная цена и отказы источников.
- **Защита выпуска** — в сборке: инварианты, необъяснённый гейт, скачок заголовка без новой книги, новых фактов или записки, закрытая запись журнала, расходящаяся с `actuals.json`, контракт `x5-v1`, потолок размера (`docs/MODEL.md` §13, `docs/PAYLOAD.md`).
- **Публикация:** ветка `data` переписывается одним коммитом; перед этим голова ветки сверяется с коммитом, прочитанным шагом состояния в начале прогона (`--expect-commit`): если ветка изменилась во время прогона (например, откат), публикация падает, ветка не тронута, следующий прогон начнёт с нового состояния. Выпуск с тем же `payload_sha256` не публикуется повторно; журнал прогнозов сверяется с лежащим в ветке — прошлые записи неизменны.
- **Сверка:** конвейер читает боевую дверь, пока она не отдаст новый `payload_sha256`; ждать приходится до ≈10 минут — raw.githubusercontent.com кэширует ответ до 5 минут, дверь — ещё 60 с.
- **Keepalive:** GitHub отключает расписание публичного репозитория после 60 дней без активности; последний шаг конвейера (идёт всегда) читает состояние workflow и включает заново только уже включённый (`active`). Отключённый вручную или GitHub workflow шаг не трогает — ручная пауза держится, включает владелец своей учётной записью.
- **CI** (`ci.yml`) и проверки документов (`docs.yml`) — раздел 9.

### 5.1. Живые входы (`indicators/`, каждый прогон)

- Живыми в оценку идут только цена и дата оценки; миры, режимы и остальные суждения — по книге.
- Негодная цена — в том числе цена с датой сделки раньше последней принятой — заменяется последней принятой из прошлого выпуска (плашка на витрине, строка в сводке прогона); нет годной цены и нет запасной — провал шага, выпуска нет. Отказ второстепенного источника — строка в `live.errors`, выпуск выходит.
- Сырые ответы пишутся в `var/raw/<источник>/<дата UTC>/` до разбора и уезжают в артефакт прогона.
- cbr.ru закрыт DDoS-Guard: запросы к нему идут с родным заголовком `Python-urllib/3.x`; rosstat.gov.ru с раннеров GitHub не отвечает — сборщиков Росстата нет (`ops/README.md`, «Грабли»).

### 5.2. Факты (`data/facts/`)
- Отчётная база — якорь книги (`meta.anchor_period`, `meta.facts_date`), всё в базисе до МСФО 16. У каждого числа — источник (`src`: файл › лист!ячейка или страница) или формула (`calc`); нераскрытое — `null`, а не 0: ядро откажет там, где число нужно.
- Файлы и поля — `data/facts/SCHEMA.md`; документы-источники, sha256 и сверка — `docs/FACTS.md`. Первичка лежит в `H\reference\primary\` (хэши — `SHA256SUMS`) и в репозиторий не кладётся.
- Факты якоря собирает `ops/tools/build_facts.py` (нужен openpyxl; первичка — `--primary` или `X5_PRIMARY`, по умолчанию `../x5-850-handoff/reference/primary`; соседние входы — `--workspace` или `X5_WORKSPACE`): читает первичку и пишет заново все файлы `data/facts/`, кроме `actuals.json`, и `data/calendar.json`. Пересборка воспроизводит их байт в байт — `tests/test_facts.py::test_builder_reproduces_facts` (метка `primary`: идёт в любом локальном прогоне на ноутбуке с первичкой рядом и openpyxl, в том числе в тестах такта; на раннерах GitHub пропускается с причиной); остальные проверки фактов — `tests/test_facts.py`.
- Руками между отчётами правятся: `actuals.json` (факты журнала), `guidance.json` (прогноз компании), `dividends.json` (реестр объявленных дивидендов), `calendar.json` — раздел 10.3.
  - `actuals.json` ведёт только человек: сборщик пишет его шаблон (описание формата и пустой список), лишь если файла нет, внесённые факты не перезаписывает, тест пересборки его не сверяет. Факт журнала — правка `data/facts/actuals.json` и коммит, в сборщик он не дублируется.
  - `guidance.json`, `dividends.json` и `calendar.json` сборщик переписывает: та же правка — тем же коммитом в `ops/tools/build_facts.py`, иначе пересборка её откатит и тест пересборки упадёт (`python -m pytest -q -rs -m primary` на ноутбуке с первичкой).

### 5.3. Календарь (`data/calendar.json`)
События на 12 месяцев вида `trading_update`, `ifrs`, `dividend`, `cbr`; `confirmed: false` — дата по прецеденту (прецедент — в `note`). Выпуск берёт отсюда события витрины, дату ближайшего отчёта и ожидаемые отсечки для флага `dividend_register`. Правится руками: `as_of` — дата правки, события — в пределах года от неё и по порядку, у каждого — `src`, у оценочного — прецедент в `note` (`tests/test_facts.py::test_calendar_events`). Ритм раскрытия X5 — `docs/INDICATORS.md`, «Календарь X5».

## 6. Модель: экономика и логика

Полностью — `docs/MODEL.md` (номера параграфов ниже — его) и книга `data/assumptions/ASSUMPTIONS-BOOK.md`.

**Цепочка расчёта:**
1. **Клетка** (§4): сеть (валовые открытия и закрытия, эффективная площадь с созреванием новой), выручка год к году к тому же полугодию (площадь × чек × трафик × прочая выручка), маржа скорр. EBITDA по режиму плюс затухающее отклонение AR(1), LTI отдельной строкой, capex (поддерживающий + открытия + инфраструктура), оборотный капитал, операционная касса, аренда, налог одной корзиной, путь долга с дивидендами по политике — полугодия от якоря до `meta.last_period` и терминал (§6).
2. **Сетка** (§3): 36 клеток = 3 мира ставок (N «нормализация», H «высокие надолго», M «рыночный как есть» — общие с Магнитом) × 4 режима маржи (стресс, дно, частичный и полный возврат) × 3 уровня capex; вероятности — из книги.
3. **Дисконт** (§5): APV — поток без рычага по ставке активов (кривая своего мира + β_u × ERP) плюс налоговый щит, минус вычеты финансирования: издержки размещения долга, проценты сверх справедливого спреда (спреды base во всех мирах), кэрри финансовой подушки; дата оценки внутри полугодия, перекат по форвардам кривой книги.
4. **Слои и точка** (§8): три набора весов миров на одних клетках — «рыночные ставки как есть» (низ), «вменённые рынком», «свой макро-взгляд» (верх); точка = низ + λ·(верх − низ).
5. **Мост и цена** (§7): требования D — чистый долг якоря, операционная касса, строки моста, денежный результат прошедшего времени, объявленные дивиденды с даты отсечки; цена = [(V0 − D) + выручка от продажи казначейского пакета по k × рыночной цены]·(1 − дисконт за управление)/выпущенные акции.
6. **Полоса** (§9): прогоны латинского гиперкуба по осям книги в их диапазонах (`valuation.uncertainty`); печатаются медиана и полосы 80 % и 50 % с шагом печати книги.
7. **Сверка с рынком:** V\* и цена 1 % EV (§7.3), обратный DCF (§11), «что даст отчёт» и нейтральная маржа (§12); правило A-P2u (§10) двигает вероятности режимов по фактам маржи, внесённым в книгу.

**Принципы** — те же, что у Магнита: APV, а не WACC; один согласованный мир ставок на клетку; распределение, а не точка; сверять с рынком, но не подгонять; факт, допущение и расчёт разделены — в коде нет чисел книги и фактов; `null ≠ 0`; все деньги до МСФО 16.

**Живое и замороженное.** Живыми остаются цена акции и дата оценки. При замороженной книге точка растёт с датой оценки (дисконт катится по форвардам, требования уменьшаются на денежный результат) — это ожидаемая доходность капитала, а не новость; «что изменилось» печатает этот вклад отдельно.

**Числа книги** на её входах — `data/assumptions/results.json` (машинный вид) и `run_output.txt` (текстом); что из них печатается — раздел 1.

## 7. Ближайший отчёт и журнал прогнозов

Полностью — `docs/INDICATORS.md`. Коротко:
- **Открытое полугодие** — самое раннее прогнозное без внесённого в книгу факта; дата отчёта — `data/calendar.json`.
- **Что считается:** ожидание модели (маржа и рост выручки по клеткам слоя «свой взгляд»), прогноз компании на год и что он требует от полугодия, три наивных эталона, «что даст отчёт» — медиана и точка при каждом значении факта маржи, нейтральная маржа.
- **Журнал прогнозов:** одна неизменяемая запись на цель и полугодие — прогноз модели и эталоны до отчёта, факт и ошибки после; факт вносится в `data/facts/actuals.json`, ошибочный исправляется переоткрытием записи (раздел 10.3). Правило допуска — `docs/INDICATORS.md`, «Правило допуска».
- **К цене журнал не подключён.** Факт отчёта входит в цену только новой версией книги — наблюдением правила A-P2u или перезаякориванием.

## 9. Проверки и качество

Что чем проверяется — `docs/MODEL.md` §16; сверка с контрольной моделью — `docs/CONTROL-MODEL.md`.
- **Регрессия книги** (`tests/test_book_results.py`): `results.json` и `run_output.txt` выпускает ядро (`python -B -m model.book_results`), свежий расчёт обязан их воспроизвести; раздел `band` (полоса, обратный DCF, «что даст отчёт») — метка `ci_only`.

- **Выпуск** — в самой сборке (`model/payload.py::validate`, `model/checks.py`) и шагом «Проверка контракта»: блоки контракта, конечность чисел, размер, хэш, печать = округлению, инварианты, гейты с объяснениями, защита заголовка.
- **Прогон «в будущем»** (`tests/test_time_travel.py`): точка растёт с датой плавно, без скачков на границах полугодий и датах отсечки; сборка на +30/+90/+180 дней от даты книги без новых блокирующих причин (`ci_only`).
- **Витрина:** CSP и хэш темы, вес `web/`, шесть экранов, без дисклеймеров, витрина читает только объявленные блоки, ползунок воспроизводит заголовок, дверь данных под Node (`tests/test_web_*.py`).
- **Документы:** числа результатов книги = `results.json` (`tests/test_render_numbers.py`, в том числе итоги и цены ошибки в тексте книги), `ops/README.md` = workflow (`tests/test_ops_readme.py`), `docs/CONTROL-MODEL.md` свеж (`tests/test_control_model.py`).
- **Метки** (`pytest.ini`, `tests/conftest.py`): `network` — только при `X5_NETWORK=1`; `ci_only` — только при переменной окружения `CI`; `primary` — только там, где есть openpyxl и первичка рядом с репозиторием (входы сборщика фактов), иначе пропуск с причиной; `docs` — сверка документов; `slow` — для отбора. Пропуск теста без одной из меток — провал.
- **Где что идёт:** конвейер — тесты такта (без `network`, `ci_only`, `docs`); CI (`ci.yml`, push и PR в `main`, кроме коммитов из одних `*.md`) — всё, кроме `network`, плюс сборка на входах книги `--book --fast` и проверка контракта; `docs.yml` (push и PR в `main`, где менялся хоть один `*.md`) — тесты `-m "docs and not network"`. CI и конвейер на push идут параллельно: конвейер CI не ждёт. Пересборка фактов (`primary`) идёт только на ноутбуке с первичкой: на раннерах GitHub нет ни первички (репозиторий публичный), ни openpyxl — там тест пропускается, причина видна (`pytest -rs`).

## 10. Процедуры и правила

### 10.1. Ежедневно (ничего делать не нужно)
Конвейер идёт сам. Признаки здоровья: писем от GitHub нет; прогоны зелёные; на витрине в будни вечером — выпуск этого дня, ярлык выпуска зелёный.

**Что на бою** — версия книги, код, выпуск, время сборки, дата оценки:
```
gh run list --workflow pipeline.yml --limit 5
curl -s -A "Mozilla/5.0" https://tzi-850-x5.pages.dev/api/model | python -c "import json,sys; m=json.load(sys.stdin)['meta']; print(m['book_version'], m['engine_commit'][:8], m['payload_sha256'][:12], m['generated_at'], m['valuation_date'])"
curl -sI -A "Mozilla/5.0" https://tzi-850-x5.pages.dev/api/model
```
Во втором ответе `Last-Modified` = `meta.generated_at`, `x-data-source` — откуда дверь взяла выпуск (раздел 10.2). `engine_commit` — HEAD сборки. История выпусков, откатов и переоткрытий записей журнала — `git fetch origin data && git show origin/data:history.json`.

### 10.2. Если что-то сломалось
- **Красный прогон конвейера** (письмо GitHub): `gh run view <id> --log-failed`; последняя строка — «ПРОВАЛ на шаге …: причина», что значит каждый шаг — `ops/README.md`, «Шаги конвейера». Прежний выпуск остаётся на витрине. Починить → push (правка в каталогах кода и данных запустит конвейер сама) или `gh workflow run pipeline.yml`; кнопку Re-run не использовать — повтор идёт на старом коммите (раздел 4, «Код прогона и голова `main`»).
- **Сборка упала на гейте:** нет объяснения, срок объяснения истёк (действует включительно) или масса вне коридора — записать или обновить объяснение в `data/assumptions/gate_explanations.yaml` (это не версия книги) и закоммитить.
- **Сборка упала на скачке заголовка** без новой книги или фактов: если скачок задуман (правка кода), — записка в `data/assumptions/release_notes.yaml` с ожидаемой точной медианой, допуском и сроком; иначе — искать причину.
- **Откат** на прошлый выпуск — только командой, из рабочей копии: `python ops/publish.py --rollback --note "<почему>"` (`latest.json` := `previous.json`, строка `rollback` с причиной в `history.json`, журнал не трогается); проверка — `ops/README.md`, «Откатить выпуск». Прогон, идущий в этот момент, откат не затрёт: его публикация упадёт на сверке головы ветки. Ручных коммитов в ветку `data` нет — следующая публикация их сотрёт. Если причина не устранена — остановить расписание `gh workflow disable pipeline.yml` и снять идущий прогон `gh run cancel <id>`, иначе следующий прогон опубликует новый выпуск поверх отката. Keepalive отключённый workflow не включает; обратно — владелец своей учётной записью (`gh workflow enable pipeline.yml`; письма пойдут ему).
- **Витрина пишет «Выпуск ещё не опубликован» или «Источник данных временно недоступен»** (ответ `/api/model` 503, заголовок — по телу ответа): «Выпуск ещё не опубликован» — `not published yet`, в ветке `data` нет `latest.json`, запасных копий нет; «Источник данных временно недоступен» — `upstream unavailable`, прочий сбой GitHub (в том числе источник не ответил за 8 с — дверь дольше не ждёт) при пустых запасных копиях. «Данные недоступны» — другой код, сеть или дверь не ответила витрине за 20 с. `x-data-source: cache-fallback` — GitHub не ответил, дверь отдаёт запасную копию, `Last-Modified` старый.
- **Выпуск стареет** (тревога сторожа в Telegram «850x5 · данные перестали обновляться» после 80 часов без публикации, плашка «Выпуску N дней» — после 96): проверить, не отключено ли расписание, — `gh workflow list`; включить — владелец своей учётной записью, `gh workflow enable pipeline.yml`.
- **Плашки флагов** (публикацию не блокируют): `book_update` — живая кривая ОФЗ ушла от кривой книги или книга старше предела (`checks.book_update` книги) → новая версия книги (10.4); `dividend_register` — ожидаемая отсечка из календаря прошла, а объявленного дивиденда в реестре нет → запись в `data/facts/dividends.json` (10.3); `price_fallback` — живая цена не принята, причина — `live.price.reason`.

### 10.3. Квартальный отчёт X5 и дивиденды
Ритм раскрытия и что приносит каждый отчёт — `docs/INDICATORS.md`, «Календарь X5».
- **Трейдинг-апдейт** (выручка, LFL, магазины) входом модели не является: подтвердить даты следующих событий в `data/calendar.json` (`confirmed: true`).
- **МСФО за 1-й и 3-й кварталы** — внутри полугодия, журнал не трогается. Факт 3-го квартала можно внести частичным наблюдением маржи второго полугодия новой версией книги (значение и погрешность — раздел A-P2u книги); для 1-го квартала такого правила в книге нет.
- **МСФО за 2-й квартал (1П) и за год (2П) закрывают полугодие:**
  1. Первичку — в `H\reference\primary\`, хэш — в `SHA256SUMS`.
  2. Факты журнала — две записи в `data/facts/actuals.json`: `x5.adj_margin` (скорр. EBITDA до МСФО 16 / выручка полугодия, доля) и `x5.revenue_growth` (рост выручки полугодия год к году, доля), с периодом и днём публикации `reported_on`; `value` — узел факта `{"v": доля, "src": "файл первички › место"}` (формат — поле `description` файла; число без узла журнал не принимает, сборка падает). Формат записей проверяет `tests/test_facts.py::test_actuals_entries_follow_the_format`. `actuals.json` ведёт только человек — сборщик фактов его не перезаписывает, в сборщик запись не дублируется. Факт вносится один раз. Ошибочный исправляется переоткрытием записи: `python ops/publish.py --reopen <id записи> --note "<почему>"`, затем правка `actuals.json` в `main` (объяснение — в сообщении коммита); выпуск закроет запись исправленным фактом. Правка `actuals.json` без переоткрытия роняет сборку с этой же подсказкой; ручных правок `journal.json` в ветке `data` нет (`ops/README.md`, «Исправить факт»).
  3. Коммит в `main` запускает конвейер: выпуск закроет записи журнала (факт и ошибки).
  4. Новая версия книги (10.4). Минимум — факт полугодия в `joint.regime_update.observations` (погрешность 0): правило A-P2u сдвинет вероятности режимов и отклонение маржи, открытым станет следующее полугодие, и журнал запишет прогноз на него; `valuation.next_report` книги — на следующее полугодие. Полностью — перезаякоривание: факты на новый якорь (`ops/tools/build_facts.py` на новой первичке, `docs/FACTS.md`; `tests/test_facts.py` закреплён на якорь — `ANCHOR_DATE` и сверки — и переписывается вместе с фактами) и в книге `meta.anchor_period`, `facts_date`, `first_period` и всё, что привязано к якорю (цель маржи на якоре, траектории с ключами полугодий, миры — ровно полугодия от `first_period`; закрытая схема это проверяет). Инструмента перезаякоривания нет (раздел 12); пока книга старая, модель считает дальше — закрытое полугодие входит в требования перекатом (`docs/MODEL.md` §5, §7.1).
- **Прогноз компании** на год (выходит с годовым отчётом в марте, пересмотры — вне календаря) — `data/facts/guidance.json`.
- **Дивиденды:** решение о выплате — запись в реестр `data/facts/dividends.json` (дата отсечки, дата реестра, сумма, флаг `cash_in_company_at_facts_date` — его смысл в `data/facts/SCHEMA.md`); требованием она становится с даты отсечки. Флаг `dividend_register` напомнит, если ожидаемая отсечка из календаря прошла, а записи нет.
- `guidance.json`, `dividends.json` и `data/calendar.json` переписывает и сборщик фактов: та же правка — тем же коммитом в `ops/tools/build_facts.py`, перед push — `python -m pytest -q -rs -m primary` на ноутбуке с первичкой (раздел 5.2); `actuals.json` — только сам файл.
- Каждый коммит в `data/` запускает конвейер.

### 10.4. Как менять допущение и пересобирать миры
- Только новой версией книги, никогда правкой кода; решает о ней владелец или ведущий. Канон книги — `data/assumptions/assumptions.yaml` вместе с текстом `data/assumptions/ASSUMPTIONS-BOOK.md`; что изменилось в версии и почему — журнал версии `data/assumptions/V<версия>-CHANGES.md`. Порядок — `data/assumptions/README.md`, «Новая версия книги».
- **Миры ставок общие с Магнитом 850oa**: пересобираются вместе с ним — после заседания ЦБ со среднесрочным прогнозом (даты — `data/calendar.json`, `cbr`) или по флагу `book_update`, как только Магнит выпустит свою версию книги с новыми мирами; перенос — `data/assumptions/README.md`, «Миры ставок»; что перенесённые миры совпадают с книгой Магнита на её теге, проверяет `python ops/tools/check_worlds.py` (шаг рецепта).
- Не версия книги (правятся в любой день): объяснения гейтов, записки о скачках, факты, календарь.

### 10.5. Выкладка витрины
Витрина (`web/`) и функции (`functions/`) выкладываются с ноутбука, из корня рабочей копии на коммите `main`:
```
npx wrangler@4.135.0 pages deploy web --project-name tzi-850-x5 --branch main
```
Версия wrangler — точная; `--branch main` — production-ветка проекта, без неё выкладка уезжает в preview. Данные этой командой не выкладываются — их приносит конвейер. Если меняется контракт выпуска — сначала данные (push кода → конвейер публикует выпуск с новыми полями), потом витрина. После выкладки — снимки боевой витрины (`docs/DASHBOARD.md`, «Снимки»).

### 10.6. Правила работы с кодом
- Коммит в `main`, меняющий `model/`, `data/`, `indicators/`, `ops/` или `requirements.txt`, — это выкладка: конвейер сразу соберёт и опубликует выпуск на новом коде. Коммит в `tests/` конвейер не будит, но следующий прогон возьмёт тесты такта из `main`. Перед push — тесты такта и `-m docs` локально (команды — `README.md`, «Запуск»); коммит из одних `*.md` проверит `docs.yml`. Перед push правки `data/facts/`, `data/calendar.json` или `ops/tools/build_facts.py` — `python -m pytest -q -rs -m primary` на ноутбуке с первичкой: пересборка фактов должна пройти, а не пропуститься (на раннерах GitHub её нет).
- В коммит — только явные пути, не `git add -A`; переводы строк — LF (`.gitattributes`); коммиты по-русски, по одному подпункту.
- Числа книги и фактов в код не переписываются (`tests/test_no_literals.py`); книга правится только новой версией; новый ключ книги регистрируется в закрытой схеме `model/book_schema.py` тем же изменением, что и код, который его читает.
- Методика — сначала текст `docs/MODEL.md`, потом код: ядро обязано делать ровно то, что написано (по тексту написана контрольная модель).
- Новое число для экрана — сначала в выпуск (`model/payload.py` и `docs/PAYLOAD.md`), потом во фронт.
- Метки тестов: читает документ `*.md` — `@pytest.mark.docs`; долгий (полная полоса, публикация через git, прогон «в будущем») — `@pytest.mark.ci_only`; ходит в сеть — `@pytest.mark.network`; читает первичку вне репозитория — `@pytest.mark.primary`. В такте — только тесты числа и контракта.
- Тесты не зависят от «сегодня»: даты — от даты книги, «сегодня» — `model.book.today()` (подменяется `FAKE_TODAY`).
- Документы: у каждого факта один дом, остальные ссылаются; числа результатов книги пишутся только метками вида `<!--=путь формат-->…<!--/-->` (синтаксис и форматы — шапка `ops/tools/render_numbers.py`); после новой книги — `python -B ops/tools/render_numbers.py`; после правки документов — `python -m pytest -q -m docs`.
- Находку, диагноз и команду сначала проверять в объекте — в коде, данных, выпуске, — потом записывать. Агенты падают — коммитить по ходу, отчёт писать в файл.

## 12. Известные ограничения и открытые вопросы

**Модель и рынок.** На входах книги рынок ниже полосы 80 % (P(ниже рынка) — <!--=band.stats.p_below p2-->1,00<!--/--> %), и ни одно суждение в пределах своего диапазона не даёт рыночную цену (раздел 1). Как это печатает витрина и почему модель не подгоняется — `docs/DECISIONS.md`; разрыв — главный предмет проверки книги. Ограничения каждого суждения — «Чем может ошибаться» в тексте книги.

**Эксплуатация.**
1. Если GitHub отключит или сбросит расписание, письма не будет — письмо приходит только о красном прогоне. Это ловит сторож свежести вне GitHub (с 29.09.2026): `dash-watch` на VPS владельца раз в 5 минут читает `Last-Modified` двери `/api/model` и после 80 часов без публикации шлёт в Telegram «850x5 · данные перестали обновляться» со ссылкой на страницу `pipeline.yml`, после новой публикации — «данные снова обновляются». Порог — разрыв пятница → понедельник 72 ч плюс до 8 ч опоздания расписания GitHub; порог, адрес и подпись такта — строка `850x5` таблицы `PANELS` в `ops/dash-watch` служебного репозитория панелей владельца, в этом репозитории от сторожа ничего нет (`docs/DECISIONS.md`, 29.09.2026). Выпуск с прежним содержимым не переопубликуется, поэтому в биржевые каникулы длиннее выходных тревога придёт по делу; откат возвращает старый `generated_at`, и после него тревога может прийти раньше. Снимает ли keepalive через `enable` 60-дневный счётчик, документацией GitHub не подтверждено — если нет, сторож это заметит.
2. У срока объяснения гейта (`valid_until` в `gate_explanations.yaml`) нет будильника: на следующий день после срока сборка упадёт, если гейт ещё срабатывает.
3. Инструмента перезаякоривания нет: переход книги на новый отчёт — ручная новая версия (10.3).
4. Файлы фактов, которые правятся руками и которые переписывает и сборщик (`guidance.json`, `dividends.json`, `calendar.json`): правка вносится в оба места (5.2). `actuals.json` ведёт только человек — сборщик его не переписывает.
5. Статическая запасная копия двери (`/fallback/latest.json`) в выкладку не кладётся: при сбое GitHub дверь живёт на копии в кэше края Cloudflare, без неё — 503.
6. Цена конвейера — сделка вечерней сессии с задержкой бесплатного ISS 15 минут, а не закрытие основной сессии (`ops/README.md`, «Грабли»).
7. Прогноз журнала на открытое полугодие пишется один раз — первым выпуском, где полугодие открыто, — и не пересматривается.
8. R2 как второй канал данных не заведён: дверь зависит от raw.githubusercontent.com (кэш края и запасная копия страхуют кратковременный сбой).
9. Re-run прогона идёт с workflow этого прогона: у прогонов, созданных до книги 1.1.1, сверки кода с головой `main` нет, и их повтор опубликовал бы выпуск на старом коде. Такие прогоны не перезапускать (GitHub разрешает Re-run 30 дней после прогона); повтор — только `gh workflow run pipeline.yml`.

**Открытые решения (владелец или ведущий):** R2 вторым каналом (ключ, скоупнутый на бакет, выпускает только владелец); инструмент перезаякоривания до отчёта FY2026 — и как быть с мирами: МСФО X5 за год выходит раньше отчёта Магнита, а траектории миров обязаны начинаться с нового первого полугодия, то есть перезаякоренная книга X5 уже не будет побайтной копией миров Магнита; вносить ли факт 3-го квартала частичным наблюдением.

## 13. Словарь
- **Владелец** — решает о выкладке и открытых вопросах; о версии книги — он или **ведущий**, который пишет книгу и проверяет находки. **Исполнитель** правит код и документы по заданию, книгу не меняет.
- **APV** — стоимость без рычага + налоговый щит; **ставка активов** — бескупонная ставка мира + β_u × ERP.
- **Мир ставок** — N, H или M; **режим маржи** — стресс, дно, частичный или полный возврат; **клетка** — мир × режим × уровень capex; **сетка** — 36 клеток; **слой** — взвешивание клеток весами миров; **V0** — ожидаемая стоимость бизнеса слоя.
- **D** — требования на дату оценки; **казначейский пакет** — n казначейских акций, в цене проданы по k × рыночной цены; **внутренняя стоимость** — [(V0 − D) + n·k·P_рынок]·(1 − g)/(N + n), **g** — дисконт за управление; **V\*** — стоимость бизнеса, при которой та же функция «EV → цена» даёт рыночную цену; **цена 1 % EV** — прирост цены при V0 × 1,01.
- **Точка при центральных значениях** — цена при значениях книги всех суждений; **λ** — вес своего макро-взгляда, положение на оси ставок; **вклад взгляда на инфляцию и ставки** — верх − низ оси.
- **Полоса** (A-V9) — распределение центра по суждениям книги в их диапазонах, P10–P90 (80 %) и P25–P75 (50 %); **медиана по суждениям** — печатаемый заголовок; **вклад оси** — доля квадрата ранговой корреляции оси с центром.
- **Обратный DCF** — значение одного суждения, при котором печатаемая медиана равна рынку; **нейтральная маржа** — факт отчёта, при котором медиана не меняется; **A-P2u** — обновление вероятностей режимов по фактам маржи.
- **Якорь** — последнее отчётное полугодие книги; **открытое полугодие** — самое раннее прогнозное без факта в книге; **перезаякоривание** — перенос книги на новый отчёт; **перекат** — перенос дисконта и требований к дате оценки.
- **Книга** — книга допущений; **таблицы книги** — `results.json` и `run_output.txt`; **регрессия книги** — свежий расчёт против таблиц; **метка** — место числа результата книги в документе.
- **Гейт** — проверка правдоподобия с письменным объяснением; **инвариант** — тождество, блокирующее сборку; **флаг** — совещательная плашка; **записка** — разрешение на задуманный скачок заголовка; **контракт** — проверки выпуска перед публикацией (`validate`).
- **Ожидание модели** — средняя маржа ядра по клеткам слоя «свой взгляд»; **эталон** — наивный прогноз для зачёта; **журнал** — неизменяемые записи прогноза и факта; **правило допуска** — `docs/INDICATORS.md`.
- **Справедливый спред** — спреды долга base книги во всех мирах: проценты сверх него (кредит stress мира M) вычитаются из EV; **вычеты финансирования** — PV издержек размещения, процентов сверх справедливого спреда и кэрри финансовой подушки.
- **Контрольная модель** — независимая реализация по тексту методики; **такт** — прогон конвейера; **тесты такта** — без меток `network`, `ci_only`, `docs`; **дверь** — `/api/model`; **ветка `data`** — опубликованные выпуски; **переоткрытие** — `publish.py --reopen`: у закрытой записи журнала снова нет факта, следующий выпуск закроет её исправленным; **FAKE_TODAY** — подмена «сегодня» для прогона «в будущем».
